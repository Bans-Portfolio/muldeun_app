물든의 캔버스(색칠) 시스템과 포인트, 수익 모델 설계를 정리합니다.

- **상태**: 기획 확정 (구현은 단계적)

## 1. 캔버스 = 색칠 도안

캔버스는 **정해진 도안(테두리만 있는 그림)을 모은 색으로 채우는 색칠공부**다.
완성된 모습은 미리 디자인되어 있고, 사용자는 산책으로 모은 색을 칠해 그 모습을 완성해간다.
(예시 도안: 무지개, 튤립, 작은 집, 작은 마을, 카피바라 산책 등)

### 도안 선택
- 여러 도안을 갤러리처럼 보여주고, 사용자가 채우고 싶은 도안을 고른다.
- 잠긴 도안은 잠금 상태로 표시한다.

### 해금 조건
- 쉬운 도안은 처음부터 열려 있다.
- 어려운 도안은 **쉬운 도안 3개 이상 완성** 시 해금된다.
- (난이도/해금 개수는 도안별로 조정 가능)

### 채색 방식 — 수동
- 모은 색은 팔레트에 재고로 쌓인다.
- 사용자가 색을 골라 도안의 **특정 영역을 직접 터치해 칠한다.**
- 자동 채색이 아닌 이유: 한 도안에 **같은 색을 2번 이상** 칠해야 하는 경우가 있어, 어느 칸을 칠할지 사용자가 정해야 하기 때문. 칠하는 행위 자체가 보상이 된다.

### 색 소모 (재고 방식)
- 도안이 요구하는 색의 수만큼 기록으로 모아야 한다.
  - 예: 도안의 빨강 영역이 3칸 → 빨강 기록 3개 필요.
- 한 칸 칠할 때마다 해당 색이 **하나씩 소모**된다.
- 현재 화면의 `0/3` 표시는 이 방식에서 "빨강 3개 필요 / 0개 칠함"의 재고·진행 표시로 동작한다.
- 색이 "해제된 도구"가 아니라 "재고"이므로, 산책·기록 행위에 무게가 실린다.

## 2. 포인트(물감) 시스템

소모 방식이라 **색 부족**이 자연히 발생한다. 부족을 메우는 경로는 두 갈래이며, **항상 둘 다 열려 있어야 한다.**

> 핵심 원칙: "돈 내야만 끝낼 수 있다"가 아니라 **"기다리기 싫으면 살 수도 있다"**.
> 무료로 메우는 길(산책·기록)이 막히면 결제 거부감이 커지고 모델이 망가진다.

### 무료 획득 경로 (과금 없이)
성격별로 묶으면:

**기록 기반**
- 기록 자체 — 사진을 찍어 색을 추출·저장하면 색이 모인다 (핵심 루프)
- 연속 기록 보너스 — 연속으로 기록하면 추가 물감

**습관 기반**
- 출석 — 매일 접속/기록 시 물감
- 걸음 수 — 산책 걸음 수에 따라 물감 (※ 아래 별도 항목)

**성취 기반**
- 도안 완성 — 도안 하나를 끝내면 물감
- 세트 도감 완성 — 도안 세트를 모두 완성하면 보너스

→ 모두 "앱을 의도대로 쓰면 자연히 모인다"는 방향. 컨셉과 한 몸으로 움직인다.

### 걸음 수 포인트 (네이티브 단계)
컨셉상 최고의 보상(산책 정체성을 직접 증명)이지만, 네이티브 출시 이후 항목이다.
- **권한 필요**: iOS HealthKit / Android Health Connect. 스토어 심사 시 권한 사용 사유 설명 필요. Flutter는 `health` 패키지로 양쪽 처리 가능.
- **어뷰징 방지**: 흔들기·부정 입력 대비. **일일 상한**(하루 최대 N물감)을 둔다.
- 상한이 없으면 많이 걷는 사용자는 색을 살 이유가 사라져 결제 동기가 무너진다.

## 3. 수익 모델 (BM)

### 광고는 넣지 않는다 — 정체성
무료 포인트 획득 수단으로 보상형 광고를 흔히 쓰지만, 물든은 넣지 않는다.
- **결이 깨진다**: 조용하고 감성적인 산책·기록 경험에 시끄러운 광고가 끼면 "추억을 색으로 기록하는 앱"이 "광고 보고 재화 받는 흔한 앱"으로 내려앉는다. 인디 앱의 차별점이 무너진다.
- **핵심 루프를 약화시킨다**: 무료 포인트의 정상 경로는 "광고 시청"이 아니라 "기록하기"여야 한다. 광고는 "산책해서 모은다"는 핵심 동선에 어색한 우회로를 만든다.
- **수익 효율도 낮다**: 보상형 광고 단가는 인디 규모 트래픽에선 푼돈. 분위기를 희생한 대가가 작다.

### 유료 (네이티브 출시 후 본격화)
- **색 구매** — 부족한 색을 포인트/현금으로 메움. 결제는 도안을 칠하다 색이 부족한 **바로 그 지점**에서 제시하는 게 전환율이 높다.
- **디지털 굿즈** — 특별 도안, 테마 등.
- MVP 단계에선 "소모 방식 + 색 재고" 구조까지만 구현하고 **결제는 자리만 비워둔다.**

### 튜닝 원칙
- 무료가 너무 후하면 아무도 색을 안 산다. 너무 짜면 답답해서 이탈한다.
- 목표 지점: "꾸준히 하면 대부분 도안은 무료로 완성 가능하되, 급하거나 특정 색이 모자랄 때 결제가 한 번씩 끼어드는" 정도.
- 이 수치는 출시 후 "걸음 수 → 포인트 → 결제 전환" 등의 데이터를 보며 환산율·상한을 조정한다.

## 4. 구현 단계 구분

| 항목 | 단계 |
|------|------|
| 도안 갤러리 / 선택 / 해금 | MVP (Flutter) |
| 수동 채색 + 색 소모 처리 | MVP (Flutter) |
| 무료 포인트 (기록·연속·출석·완성) | MVP~네이티브 |
| 걸음 수 포인트 | 네이티브 (HealthKit/Health Connect) |
| 색 구매 / 디지털 굿즈 결제 | 네이티브 (자리만 MVP에 비워둠) |
| 광고 | 도입하지 않음 |
